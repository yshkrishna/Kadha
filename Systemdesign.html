01 How to Start the Interview L7 SIGNAL

Principal signal: You define the scope rather than accept whatever the interviewer implies. The candidate who skips this step designs the wrong system every single time.

📖 Step 1 — Story (Real-World Analogy)

You're a master architect hired to design an international airport. The city council says: "We need an airport." A junior architect starts sketching runways. A principal pauses: "How many passengers? Domestic or international? Budget? Swamp or bedrock?" Skip these questions, and you design a regional airport that drowns under 50M travelers — or a mega-hub that bankrupts the city serving two flights daily. In software, un-scoped design is guaranteed failure, no matter the elegance.

💥 Step 2 — What Breaks Without It

Without the first 60 seconds of scoping, you propose a single Postgres + replicas, but the interviewer assumed 500M writes/day. Design instantly obsolete. You mention Kafka — interviewer needed 100 requests/day. You've over-engineered yourself out. Cascading interview failure: Wrong assumptions → wrong architecture → interviewer loses confidence → backtracking → time runs out on an irrelevant design. Amazon US-EAST-1 2021: scaling event unscoped against blast radius — scope mismatch kills real systems, not just interviews.

🧮 Step 3 — Back-of-Envelope Math

• Bandwidth: 17,400 × 1KB ≈ 17 MB/s → 140 Mbps peak

💻 Step 7 — .NET 9 Code (Real Integration)

a) ❌ WRONG WAY

app.MapGet("/design", () => "Here's my design!"); // No scope, no telemetry

b) ✅ RIGHT WAY — Scope-Driven Health Check with OpenTelemetry

using System.Diagnostics.Metrics;
using Microsoft.Extensions.Diagnostics.HealthChecks;

public class ScopeHealthCheck : IHealthCheck
{
    private readonly int _maxQps;
    private readonly Counter<int> _requestCounter;
    private readonly Histogram<double> _latencyHistogram;
    private int _currentSecond;
    private int _requestCount;

    public ScopeHealthCheck(int maxQps, IMeterFactory meterFactory)
    {
        _maxQps = maxQps;
        var meter = meterFactory.Create("ScopeHealth");
        _requestCounter = meter.CreateCounter<int>("scope.requests_per_second");
        _latencyHistogram = meter.CreateHistogram<double>("scope.latency_ms");
    }

    public Task<HealthCheckResult> CheckHealthAsync(HealthCheckContext ctx, CancellationToken ct)
    {
        var currentSecond = Environment.TickCount / 1000;
        if (currentSecond != _currentSecond)
        {
            _currentSecond = currentSecond;
            _requestCount = 0;
        }
        _requestCount++;
        _requestCounter.Add(1);

        if (_requestCount > _maxQps * 1.5)
            return Task.FromResult(HealthCheckResult.Degraded(
                $"QPS {_requestCount} exceeds 150% of planned {_maxQps}. " +
                $"Check Redis hit ratio and DB connection pool."));

        return Task.FromResult(HealthCheckResult.Healthy($"QPS {_requestCount} within plan"));
    }
}

// NuGet: OpenTelemetry.Extensions.Hosting, OpenTelemetry.Instrumentation.AspNetCore

builder.Services.AddHealthChecks().AddCheck<ScopeHealthCheck>("scope_qps");
builder.Services.AddOpenTelemetry()

d) Real Usage — Controller

[HttpGet("/api/health")]
public async Task<IActionResult> Health([FromServices] HealthCheckService hc)
{
    var report = await hc.CheckHealthAsync();
    return report.Status == HealthStatus.Healthy ? Ok(report) : StatusCode(503, report);
}

e) Unit Test

[Fact] public void ScopeHealthCheck_DegradesWhenOverCapacity() {
    var check = new ScopeHealthCheck(100, new MeterFactory());
    for (int i = 0; i < 200; i++) check.CheckHealthAsync(default);
    var result = check.CheckHealthAsync(default).Result;

🔥 Step 10 — Failure Modes (Production Depth)

1. Interviewer Shifts Constraints Mid-Design

Scenario: "Actually, we need 500M writes/day." Detection: You notice contradiction with prior assumption. Impact: Design invalidated. Fix: "Let me re-scope. At 500M writes, caching ineffective. I'd pivot to sharded writes + async queue. Revised math: …" Prevention: State assumptions explicitly upfront. Invite correction early.

2. Time Exhaustion — Over-Scoping Early

Scenario: You spend 15min on clarifying questions. Detection: Interviewer: "We have 15min left." Impact: Rush core design, miss depth. Fix: "I'll prioritize the write path and skip CDN unless time remains." Prevention: 5min max for questions then commit to architecture.

3. Over-Constraining → Wrong Architecture

Scenario: You assume strong consistency for everything → force CP system → cost 3× higher. Detection: Interviewer: "Is strong consistency worth 3× cost here?" Impact: Budget-infeasible design. Fix: "You're right. Feed can be eventual. Only payment needs CP." Prevention: Apply CAP per-service, not system-wide.

4. Missing Non-Functional Requirement

Scenario: You never discussed latency budget. Design has p99=500ms. Interviewer reveals p99=50ms target. Detection: Late-stage contradiction. Impact: Redesign under time pressure. Fix: "At 50ms p99, CDN is mandatory. I'll add edge caching + reduce DB hops." Prevention: Ask Q1 (latency vs consistency) first — sets performance envelope.

5. Scope Creep via "What Else?"

Scenario: After design, interviewer: "How about analytics? Fraud detection?" Detection: Feature avalanche. Impact: Original design bloated, incoherent. Fix: "Analytics is a separate read path — I'd add async event streaming. It doesn't change core design." Prevention: Explicitly separate core vs auxiliary features early.

🧮 Step 3 — Envelope Math + Latency Budget

📐 Throughput:
100M MAU → 3.3M DAU × 20 actions = 66M req/day → 764 avg QPS × 3 = 2,292 peak QPS

⏱️ Latency Budget (p99 <100ms):
• Network (LB→App→DB→App→LB): 5ms
• App processing (.NET 9): 10ms
• DB query (indexed, p99): 5ms
• Cache (Redis, p99 <1ms): 1ms
• Headroom (GC, serialization, OS): 4ms
Total budgeted: 25ms. Target p99=100ms → 4× budget headroom for tail latency.

💾 Storage: 500M records × 2KB × 3 (repl) × 1.5 (index) = 4.5TB → $1,200/mo
🌐 Bandwidth: 2,292 QPS × 5KB = 11.5 MB/s → 92 Mbps → $890/mo egress
🖥️ Servers: 2,292 ÷ 500 QPS/pod = 5 + 2 redundancy = 7 pods → $403/mo
Total: ~$2,493/mo. Surprise: Egress ($890) > Compute ($403).

Eliminations:
• Single DB: ~2K QPS limit (indexed reads, 5-10ms, pooled) → eliminated (need 2.3K)
• No cache: DB replicas = 3 × $400 = $1,200 vs Redis $400 → replicas eliminated (3× cost, identical SLA)
• Serverless: p99 cold start >200ms → eliminated (violates 100ms budget)

💻 Step 7 — .NET 9 Code (Real Resilience)

a) ❌ WRONG WAY

var maxConn = 100; // No math. Breaks at 2.3K QPS.

b) ✅ RIGHT WAY — CapacityPlan + Resilience

using Microsoft.Extensions.Http.Resilience;
using Polly;

public sealed record CapacityPlan(int PeakQps, int DbMaxConn, double RequiredCacheHR, int PodCount)
{
    public int ConnectionsPerPod => (int)(DbMaxConn * 0.8 / PodCount);
    public bool IsDbSafe(double actualHR) => PeakQps * (1 - actualHR) <= DbMaxConn * 0.7;
}

public static class CapacityPlanner
{
    public static CapacityPlan FromDau(int dau, int actions)
    {
        int peakQps = (dau * actions) / 86400 * 3;
        int pods = (int)Math.Ceiling(peakQps / 500.0) + 2;
        int dbMax = 500;
        double requiredHR = 1.0 - (dbMax * 0.7 / peakQps);
        if (requiredHR < 0) throw new InvalidOperationException(
            $"DB capacity insufficient even at 100% cache hit. Peak QPS: {peakQps}, DB max: {dbMax}");
        return new(peakQps, dbMax, requiredHR, pods);
    }
}

c) Program.cs — Resilience + Redis

builder.Services.AddSingleton(CapacityPlanner.FromDau(3_300_000, 20));
builder.Services.AddStackExchangeRedisCache(o => o.Configuration = "redis:6379");
builder.Services.AddHttpClient("db").AddStandardResilienceHandler(o => {
    o.Retry.MaxRetryAttempts = 3;
    o.CircuitBreaker.FailureRatio = 0.5;
    o.CircuitBreaker.SamplingDuration = TimeSpan.FromSeconds(30);
});

d) Real Usage — Capacity-Aware Controller

[HttpGet] public async Task<IActionResult> Search(string q, 
    [FromServices] CapacityPlan plan, [FromServices] IDistributedCache cache) {
    double hr = await GetCacheHitRatio();
    if (!plan.IsDbSafe(hr)) return StatusCode(503, new { RetryAfter = 5 });
    var cached = await cache.GetStringAsync(q);
    if (cached != null) return Ok(cached);
    var result = await DbQuery(q);
    await cache.SetStringAsync(q, result, new DistributedCacheEntryOptions { 
        SlidingExpiration = TimeSpan.FromSeconds(30) });
    return Ok(result);
}

Array Manipulation & Prefix/Suffix Sums

Dynamic Programming Range Query
Explanation

A prefix sum array transforms an input array so each element at index i stores the cumulative sum of all elements from index 0 to i. This precomputation allows any range-sum query [L, R] to be answered in O(1) — instead of scanning through the subarray each time. A suffix sum does the same right-to-left. Together they're foundational for range queries, equilibrium index problems, and subarray analysis.

Formula / Algorithm
// Build
prefix[0] = arr[0]
prefix[i] = prefix[i-1] + arr[i] for i ≥ 1
 
// Range sum query [L, R]
sum = prefix[R] - prefix[L-1] if L > 0
sum = prefix[R] if L == 0
C# Code Example
C# · PrefixSum.cs
public class PrefixSum {
    private int[] prefix;

    public PrefixSum(int[] arr) {
        int n = arr.Length;
        prefix = new int[n];
        prefix[0] = arr[0];
        for (int i = 1; i < n; i++)
            prefix[i] = prefix[i - 1] + arr[i];
    }

    // Returns sum of arr[L..R] inclusive — O(1)
    public int RangeSum(int L, int R) {
        if (L == 0) return prefix[R];
        return prefix[R] - prefix[L - 1];
    }

    public static void Main() {
        int[] arr = { 3, 1, 4, 1, 5, 9, 2, 6 };
        var ps = new PrefixSum(arr);
        Console.WriteLine(ps.RangeSum(2, 5)); // → 19  (4+1+5+9)
        Console.WriteLine(ps.RangeSum(0, 3)); // → 9   (3+1+4+1)
    }
}
Step-by-Step Walkthrough

Given arr = [3, 1, 4, 1, 5, 9, 2, 6]:

1
Build prefix: [3, 4, 8, 9, 14, 23, 25, 31]
2
Query [2, 5]: prefix[5] - prefix[1] = 23 - 4 = 19
3
Verify: arr[2]+arr[3]+arr[4]+arr[5] = 4+1+5+9 = 19 ✓
Complexity Analysis
Time
O(n) + O(1)
Space
O(n)
Explanation
One O(n) pass to build the prefix array. Each query is then just a subtraction — O(1). Trade O(n) space once to make all future queries instant.
Why This Is Efficient
💡
Without prefix sums, each range query costs O(n). With them, we pay O(n) once at build time, then answer any number of queries in O(1). When processing millions of queries on the same array, this is a massive win. It's the foundation of 2D prefix sums, difference arrays, and segment trees.

Sliding Window Technique

Two PointersSubstring
Explanation

The sliding window technique maintains a contiguous sub-range (window) of an array or string and slides it forward to find an optimal result. Instead of recomputing from scratch on each shift, you update incrementally by removing the leftmost element and adding the new rightmost. Two variants: fixed-size (constant length) and variable-size (expands/shrinks based on a condition).

C# Code Example — Longest Substring Without Repeating Characters
C# · SlidingWindow.cs
public static int LengthOfLongestSubstring(string s) {
    var seen = new Dictionary<char, int>(); // char → last index
    int maxLen = 0, left = 0;

    for (int right = 0; right < s.Length; right++) {
        char c = s[right];
        // If char is inside current window, shrink from left
        if (seen.ContainsKey(c) && seen[c] >= left)
            left = seen[c] + 1;

        seen[c] = right;
        maxLen = Math.Max(maxLen, right - left + 1);
    }
    return maxLen;
}

// "abcabcbb" → 3  |  "pwwkew" → 3  |  "bbbbb" → 1
Step-by-Step Walkthrough

Input: "abcabcbb"

1
right=0 (a): window="a", len=1
2
right=1 (b): window="ab", len=2
3
right=2 (c): window="abc", len=3
4
right=3 (a): 'a' seen at 0 ≥ left(0) → move left=1, window="bca", len=3
5
Max length = 3
Complexity Analysis
Time
O(n)
Space
O(min(n,m))
Explanation
Each element enters and exits the window once. m = charset size (26 for lowercase, 128 for ASCII).
Why This Is Efficient
💡
Brute force checks all O(n²) subarrays. Sliding window eliminates reprocessing by reusing the previous window's computation. It's the go-to technique whenever you see: contiguous subarray, substring, consecutive elements with an optimization goal.

Kadane's Algorithm

Dynamic ProgrammingMax Subarray
Explanation

Kadane's Algorithm finds the contiguous subarray with the largest sum in a single pass. It maintains two values: maxEndingHere (maximum sum ending at the current position) and maxSoFar (global max). At each step, you decide: extend the current subarray, or start fresh from the current element.

Formula
maxEndingHere = max(arr[i], maxEndingHere + arr[i])
maxSoFar = max(maxSoFar, maxEndingHere)
C# Code Example
C# · Kadane.cs
public static (int sum, int start, int end) MaxSubarray(int[] arr) {
    int maxEnd = arr[0], maxSoFar = arr[0];
    int start = 0, end = 0, tempStart = 0;

    for (int i = 1; i < arr.Length; i++) {
        if (arr[i] > maxEnd + arr[i]) {
            maxEnd = arr[i];
            tempStart = i;         // Start fresh
        } else {
            maxEnd += arr[i];      // Extend current
        }

        if (maxEnd > maxSoFar) {
            maxSoFar = maxEnd;
            start = tempStart;
            end = i;
        }
    }
    return (maxSoFar, start, end);
}

// [-2,1,-3,4,-1,2,1,-5,4] → sum=6, indices=[3,6] → {4,-1,2,1}
Step-by-Step Trace
Trace: [-2,1,-3,4,-1,2,1,-5,4]
i=0: maxEnd=-2,  maxSoFar=-2
i=1: max(1, -2+1=-1) → maxEnd=1,   maxSoFar=1
i=2: max(-3,1-3=-2) → maxEnd=-2,  maxSoFar=1
i=3: max(4,-2+4=2)  → maxEnd=4,   maxSoFar=4
i=4: max(-1,4-1=3)  → maxEnd=3,   maxSoFar=4
i=5: max(2,3+2=5)   → maxEnd=5,   maxSoFar=5
i=6: max(1,5+1=6)   → maxEnd=6,   maxSoFar=6  ✓ Result
i=7: max(-5,6-5=1)  → maxEnd=1,   maxSoFar=6
i=8: max(4,1+4=5)   → maxEnd=5,   maxSoFar=6
Answer: 6
Complexity Analysis
Time
O(n)
Space
O(1)
Explanation
Single pass, two variables. No extra memory needed beyond the input array. Brute force is O(n²) checking all start/end pairs.

Longest Increasing Subsequence

Dynamic ProgrammingBinary Search
Explanation

LIS finds the longest subsequence where each element is strictly greater than the previous. A subsequence need not be contiguous. Two approaches: O(n²) DP and the optimal O(n log n) patience-sorting approach using a tails[] array maintained in sorted order.

C# Code Example — O(n log n) Solution
C# · LIS.cs
public static int LengthOfLIS(int[] nums) {
    var tails = new List<int>();

    foreach (int num in nums) {
        // Binary search: first index where tails[i] >= num
        int lo = 0, hi = tails.Count;
        while (lo < hi) {
            int mid = (lo + hi) / 2;
            if (tails[mid] < num) lo = mid + 1;
            else hi = mid;
        }
        if (lo == tails.Count) tails.Add(num);   // New longest
        else tails[lo] = num;                    // Replace for future
    }
    return tails.Count;
}

// [10,9,2,5,3,7,101,18] → 4  (e.g. [2,3,7,18])
Patience Sort Trace
Trace: [10,9,2,5,3,7,101,18]
10  → tails=[10]
9   → replace tails[0]=9    tails=[9]
2   → replace tails[0]=2    tails=[2]
5   → append               tails=[2,5]
3   → replace tails[1]=3    tails=[2,3]
7   → append               tails=[2,3,7]
101 → append               tails=[2,3,7,101]
18  → replace tails[3]=18   tails=[2,3,7,18]
Answer = tails.Count = 4
Complexity Analysis
Time
O(n log n)
Space
O(n)
Explanation
Binary search O(log n) for each of n elements. tails array holds at most n elements. Naive DP is O(n²).

0/1 Knapsack Problem

Dynamic ProgrammingOptimization
Explanation

Given n items each with weight w[i] and value v[i], and a knapsack of capacity W — maximize total value. Each item is included (1) or excluded (0), no fractions. The DP table dp[i][w] stores the max value using the first i items with capacity w.

Recurrence
if w[i] > w: dp[i][w] = dp[i-1][w] // too heavy, skip
else: dp[i][w] = max(dp[i-1][w], dp[i-1][w-w[i]] + v[i])
 
// Answer: dp[n][W]
C# Code Example
C# · Knapsack.cs
public static int MaxValue(int[] weights, int[] values, int capacity) {
    int n = weights.Length;
    int[,] dp = new int[n + 1, capacity + 1];

    for (int i = 1; i <= n; i++) {
        for (int w = 0; w <= capacity; w++) {
            dp[i, w] = dp[i - 1, w];   // Default: skip item i
            if (weights[i-1] <= w) {
                int withItem = dp[i-1, w - weights[i-1]] + values[i-1];
                dp[i, w] = Math.Max(dp[i, w], withItem);
            }
        }
    }
    return dp[n, capacity];
}

// w=[1,3,4,5] v=[1,4,5,7] W=7 → 9  (items 2+3: weight=7, value=9)
Complexity Analysis
Time
O(n × W)
Space
O(n × W) → O(W)
Explanation
Fill every cell of the n×W table. Can reduce to O(W) space by iterating weights backwards in a 1D array (each row only depends on previous row).

Fibonacci — Dynamic Programming

MemoizationTabulation
Explanation

The Fibonacci sequence is the canonical example for understanding DP evolution: naive recursion (O(2ⁿ)) → memoization → tabulation → space-optimized rolling variables (O(1) space). The pattern of "only need the last two values" applies to many 1D DP problems.

C# Code — All 4 Approaches
C# · Fibonacci.cs — Four Approaches
// ❌ Approach 1: Naive Recursion — O(2^n) — never use in interviews
public static long FibNaive(int n) =>
    n <= 1 ? n : FibNaive(n-1) + FibNaive(n-2);

// ✓ Approach 2: Top-Down Memoization — O(n) time, O(n) space
private static Dictionary<int, long> memo = new();
public static long FibMemo(int n) {
    if (n <= 1) return n;
    if (memo.ContainsKey(n)) return memo[n];
    return memo[n] = FibMemo(n-1) + FibMemo(n-2);
}

// ✓ Approach 3: Bottom-Up Tabulation — O(n) time, O(n) space
public static long FibTable(int n) {
    if (n <= 1) return n;
    long[] dp = new long[n + 1];
    dp[0] = 0; dp[1] = 1;
    for (int i = 2; i <= n; i++) dp[i] = dp[i-1] + dp[i-2];
    return dp[n];
}

// ⭐ Approach 4: Space-Optimized — O(n) time, O(1) space  ← BEST
public static long FibOptimal(int n) {
    if (n <= 1) return n;
    long prev2 = 0, prev1 = 1;
    for (int i = 2; i <= n; i++) {
        long curr = prev1 + prev2;
        prev2 = prev1; prev1 = curr;
    }
    return prev1;
}
// FibOptimal(50) = 12586269025
Complexity Analysis
Time
O(n)
Space
O(1)
Explanation
Rolling two-variable approach. Each F(n) depends only on the previous two values, so no array needed. This "rolling array" pattern applies to many 1D DP problems.

Sunflower spirals, nautilus shells, leaf phyllotaxis

Dijkstra's Algorithm

GraphGreedyShortest Path
Explanation

Dijkstra's finds the shortest path from a source vertex to all others in a weighted graph with non-negative edge weights. It's a greedy algorithm that always extends the cheapest known path first using a min-heap. ⚠️ Does NOT work with negative edge weights — use Bellman-Ford instead.

C# Code Example (.NET 6+ PriorityQueue)
C# · Dijkstra.cs
public static int[] ShortestPaths(List<(int to, int weight)>[] graph, int src) {
    int n = graph.Length;
    int[] dist = new int[n];
    Array.Fill(dist, int.MaxValue);
    dist[src] = 0;

    // PriorityQueue<element, priority> — .NET 6+
    var pq = new PriorityQueue<int, int>();
    pq.Enqueue(src, 0);

    while (pq.Count > 0) {
        pq.TryDequeue(out int u, out int d);
        if (d > dist[u]) continue; // Stale entry, skip

        foreach (var (v, w) in graph[u]) {
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.Enqueue(v, dist[v]);
            }
        }
    }
    return dist;
}
// Edges: 0→1(4), 0→2(1), 2→1(2), 1→3(1), 3→4(3)
// dist from 0: [0, 3, 1, 4, 7]
Complexity Analysis
Time
O((V+E) log V)
Space
O(V+E)
Explanation
Each vertex/edge processed once; heap operations cost O(log V). E edges stored in adjacency list. Dense graphs: O(V²) with simple array instead of heap.

Merge Sort — Divide & Conquer

SortingStable Sort
Explanation

Merge Sort recursively splits an array in half, sorts each half, then merges the two sorted halves. Guaranteed O(n log n) in all cases — best, average, worst. It's a stable sort (equal elements preserve relative order), unlike QuickSort which degrades to O(n²) worst-case.

C# Code Example
C# · MergeSort.cs
public static void Sort(int[] arr, int left, int right) {
    if (left >= right) return;
    int mid = (left + right) / 2;
    Sort(arr, left, mid);
    Sort(arr, mid + 1, right);
    Merge(arr, left, mid, right);
}

private static void Merge(int[] arr, int left, int mid, int right) {
    int n1 = mid - left + 1, n2 = right - mid;
    int[] L = new int[n1], R = new int[n2];
    Array.Copy(arr, left, L, 0, n1);
    Array.Copy(arr, mid + 1, R, 0, n2);

    int i = 0, j = 0, k = left;
    while (i < n1 && j < n2)
        arr[k++] = L[i] <= R[j] ? L[i++] : R[j++];
    while (i < n1) arr[k++] = L[i++];
    while (j < n2) arr[k++] = R[j++];
}

// [38,27,43,3,9,82,10] → [3,9,10,27,38,43,82]
Divide & Conquer Trace
Trace: [38,27,43,3,9,82,10]
Split:  [38,27,43]          [3,9,82,10]
Split:  [38]  [27,43]       [3,9]  [82,10]
Split:  [38]  [27] [43]     [3][9] [82][10]
Merge:  [38]  [27,43]       [3,9]  [10,82]
Merge:  [27,38,43]          [3,9,10,82]
Merge:  [3,9,10,27,38,43,82]
Complexity Analysis
Time
O(n log n)
Space
O(n)
Explanation
log n levels of recursion, O(n) work per level. O(n) auxiliary space for temporary arrays during merge. Worst-case is same as best-case — guaranteed.

Binary Search on Sorted Array

SearchMonotonic
Explanation

Binary search finds a target in a sorted array by repeatedly halving the search space. Beyond simple lookup, it generalizes to any monotonic predicate — "search on answer" problems. The overflow-safe mid calculation lo + (hi - lo) / 2 is critical in production code.

C# Code Example — Standard + Rotated Array
C# · BinarySearch.cs
// Standard binary search
public static int Search(int[] arr, int target) {
    int lo = 0, hi = arr.Length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;  // ← overflow-safe
        if (arr[mid] == target) return mid;
        if (arr[mid] < target)  lo = mid + 1;
        else                    hi = mid - 1;
    }
    return -1;
}

// Search in rotated sorted array [4,5,6,7,0,1,2]
public static int SearchRotated(int[] arr, int target) {
    int lo = 0, hi = arr.Length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] == target) return mid;
        if (arr[lo] <= arr[mid]) {         // Left half sorted
            if (arr[lo] <= target && target < arr[mid]) hi = mid - 1;
            else lo = mid + 1;
        } else {                            // Right half sorted
            if (arr[mid] < target && target <= arr[hi]) lo = mid + 1;
            else hi = mid - 1;
        }
    }
    return -1;
}
// SearchRotated([4,5,6,7,0,1,2], 0) → 4
Complexity Analysis
Time
O(log n)
Space
O(1)
Explanation
Search space halves each iteration. For n=1,000,000 → only ~20 comparisons. Linear search would need up to 1,000,000 comparisons.

Greedy Algorithms — Activity Selection

GreedyInterval Scheduling
Explanation

Activity Selection selects the maximum number of non-overlapping activities. The greedy insight: always choose the activity with the earliest finish time that doesn't conflict with already selected activities. This locally optimal choice is globally optimal — proved by a formal exchange argument.

C# Code Example
C# · ActivitySelection.cs
public static List<(int start, int end)> SelectActivities(
    int[] starts, int[] ends) {

    var activities = Enumerable.Range(0, starts.Length)
        .Select(i => (start: starts[i], end: ends[i]))
        .OrderBy(a => a.end)   // ← Key greedy step
        .ToList();

    var selected = new List<(int, int)>();
    int lastEnd = -1;

    foreach (var (start, end) in activities) {
        if (start >= lastEnd) {     // No overlap
            selected.Add((start, end));
            lastEnd = end;
        }
    }
    return selected;
}
// starts=[1,3,0,5,8,5] ends=[2,4,6,7,9,9]
// → [1,2] [3,4] [5,7] [8,9]  (4 activities)
Greedy Trace
Sorted by end time
lastEnd=-1
(1,2): start=1 >= -1 → SELECT, lastEnd=2
(3,4): start=3 >= 2  → SELECT, lastEnd=4
(0,6): start=0 <  4  → SKIP (overlaps)
(5,7): start=5 >= 4  → SELECT, lastEnd=7
(8,9): start=8 >= 7  → SELECT, lastEnd=9
(5,9): start=5 <  9  → SKIP
Result: 4 activities
Complexity Analysis
Time
O(n log n)
Space
O(n)
Explanation
Dominated by sorting. If pre-sorted by end time, reduces to O(n). O(n) to store selected activities.

Bit Manipulation — Counting Set Bits

BitwiseHamming Weight
Explanation

Bit manipulation directly operates on the binary representation of integers. Brian Kernighan's algorithm counts set bits (Hamming weight) in O(k) where k = number of 1-bits. The key trick: n &= (n-1) always clears exactly the lowest set bit of n.

Essential Bit Tricks
n & (n-1) → clears lowest set bit // core of Kernighan
n & (-n) → isolates lowest set bit
n & 1 → check if n is odd
n ^ n → 0 // XOR self = 0 (find single number trick)
a ^ b ^ a → b // XOR is its own inverse
n >> k → divide by 2^k
n << k → multiply by 2^k
C# Code Example
C# · BitManipulation.cs
// Brian Kernighan — count set bits in O(k)
public static int CountSetBits(int n) {
    int count = 0;
    while (n != 0) { n &= (n - 1); count++; }
    return count;
}

// Power of 2: exactly one bit set
public static bool IsPowerOfTwo(int n) =>
    n > 0 && (n & (n - 1)) == 0;

// Find single number (all others appear twice)
public static int SingleNumber(int[] nums) {
    int result = 0;
    foreach (int n in nums) result ^= n; // Pairs cancel
    return result;
}

// Count bits for 0..n using DP + bit trick — O(n)
public static int[] CountBitsDP(int n) {
    int[] dp = new int[n + 1];
    for (int i = 1; i <= n; i++)
        dp[i] = dp[i >> 1] + (i & 1); // dp[i/2] + (odd? 1:0)
    return dp;
}

// CountSetBits(29=11101) → 4
// IsPowerOfTwo(16)       → true
// SingleNumber([4,1,2,1,2]) → 4
// CountBitsDP(5) → [0,1,1,2,1,2]
Kernighan Trace
CountSetBits(29) — 29 = 11101₂
n=29 (11101): n &= 28 (11100) → count=1
n=28 (11100): n &= 24 (11000) → count=2
n=24 (11000): n &= 16 (10000) → count=3
n=16 (10000): n &= 0  (00000) → count=4
n=0  → stop. Return 4 ✓
Complexity Analysis
Time
O(k set bits)
Space

Iterates once per set bit. For a 32-bit int, at most 32 iterations. Modern CPUs have a POPCNT instruction that runs in a single clock cycle.

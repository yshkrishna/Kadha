Section 01

var + Collection Expression Mastery

Why var x = []; Fails

In C# 12, [] is a collection expression — a contextual expression that requires a target type. When you write var x = [], the compiler cannot infer a type because var asks for type from the right-hand side, and [] provides none. This creates a circular dependency resolved with CS9176.

C#
// ❌ ERROR CS9176 — no target type for collection expression
var x = [];
var y = [1, 2, 3];

// ✅ WORKS — target type is known from left side
List<int>        a = [];
int[]            b = [];
HashSet<string>  c = [];
IEnumerable<int> d = [1, 2, 3];

// ✅ WORKS as method argument — target type from parameter
void Accept(List<int> items) { }
Accept([1, 2, 3]);  // compiler infers List<int> from parameter
Mental Model: Collection expressions are lazy — they borrow their identity from whoever receives them. No receiver = no identity = compiler error.

Target-Typed new()

C#

HashSet<T>.Add() API Fingerprint

The single most important behavioral difference between List<T> and HashSet<T>: HashSet.Add() returns bool — true if the element was new, false if it was already present.

C#
HashSet<int> set = [1, 2, 3];

bool wasNew       = set.Add(4);  // true  — 4 is new
bool wasDuplicate = set.Add(1);  // false — 1 already present

// The elegant one-liner duplicate check pattern:
static bool HasDuplicate<T>(IEnumerable<T> source)
{
    HashSet<T> seen = [];
    foreach (T item in source)
        if (!seen.Add(item))   // false = already seen = duplicate
            return true;
    return false;
}
VS IntelliSense Tip: Type set.Add( — tooltip shows bool HashSet<T>.Add(T item). If it shows void, you have a List<T> — wrong collection for duplicate detection.

Spread Operator ..

C#
int[] first  = [1, 2, 3];
int[] second = [4, 5, 6];
int[] merged = [..first, ..second];         // [1,2,3,4,5,6]
int[] extended = [0, ..first, ..second, 7]; // [0,1,2,3,4,5,6,7]

HashSet<int> setA = [1, 2, 3];
HashSet<int> setB = [3, 4, 5];
HashSet<int> union = [..setA, ..setB];     // {1,2,3,4,5} — 3 deduped

// Spread from any IEnumerable<T>

Section 02

Every Major Collection

T[ ] — Array
Fixed-length, contiguous memory on the managed heap. Once created, length is immutable. The foundational collection — most other types store arrays internally.
O(1) index Fixed size
C# 12 Inits
int[]      a1 = new int[5];              // zero-initialized
int[]      a2 = new int[] { 1, 2, 3 };
int[]      a3 = new[] { 1, 2, 3 };     // implicit type
int[]      a4 = [1, 2, 3];             // C# 12 ✅ preferred
int[]   empty = [];                     // empty — preferred over Array.Empty<int>

// Core API
int[] arr = [10, 20, 30, 40, 50];
int len   = arr.Length;          // 5
int last  = arr[^1];             // 50 — index-from-end
int[] sl  = arr[1..4];           // [20,30,40] — new array copy
Array.Sort(arr);
int idx   = Array.BinarySearch(arr, 30);
Use when: size is known at construction, you need max cache performance, or you're calling interop/Span/socket APIs.
List<T>
Dynamically resizable array — internally holds a T[] and doubles capacity when full. Workhorse of .NET: ordered, indexed, mutable, and efficient for append-heavy workloads.
O(1) amort add O(n) insert mid
C# 12 Inits
List<int> l1 = new List<int> { 1, 2, 3 };
List<int> l2 = new() { 1, 2, 3 };
List<int> l3 = [1, 2, 3];           // C# 12 ✅
List<int> l4 = new(capacity: 256);   // pre-allocated

// Core API
list.Add(7);                    // O(1) amortized
list.AddRange([10, 11]);         // O(k)
list.RemoveAll(x => x < 3);     // O(n)
list.Sort();                     // O(n log n) in-place

// Zero-copy span access (.NET 8+)
Span<int> span = CollectionsMarshal.AsSpan(list);
Use when: default dynamic ordered collection — covers 80% of use cases. Choose T[] only when size is fixed, LinkedList when you need O(1) both-ends.
HashSet<T>
Unordered collection of unique elements backed by a hash table. Membership testing, addition, and removal are all amortized O(1). Automatically enforces uniqueness.
O(1) amort all ops Unordered
C# 12 Inits + API
HashSet<string> h1 = ["a", "b", "c"];
HashSet<string> h2 = new(StringComparer.OrdinalIgnoreCase) { "A" };

bool added = set.Add(6);      // true  — new element
bool dup   = set.Add(3);      // false — already present
bool has   = set.Contains(4); // O(1)

// Set operations
set.UnionWith(other);
set.IntersectWith(other);
set.ExceptWith(other);
bool eq = set.SetEquals(other);
Use when: deduplication, "seen" tracking in BFS, set-algebra operations. For ordered unique elements use SortedSet<T>.
Dictionary<K,V>
Hash table mapping unique keys to values. Key lookup, insertion, and removal are all amortized O(1). Insertion order preserved as implementation detail since .NET 5 — do not rely on it.
O(1) amort all ops
C# 12 Inits + API
Dictionary<string, int> d = new()
{
    ["Alice"] = 95,
    ["Bob"]   = 87
};

// Safe read — prefer TryGetValue over indexer
if (d.TryGetValue("Alice", out int score))
    Console.WriteLine(score);

// GetValueOrDefault — .NET 5+
int eve = d.GetValueOrDefault("Eve", defaultValue: 0);

// Deconstruct in foreach
foreach ((string name, int s) in d)
    Console.WriteLine($"{name}: {s}");

// ContainsKey is O(1); ContainsValue is O(n)
bool hasAlice = d.ContainsKey("Alice");  // O(1)
bool has95    = d.ContainsValue(95);      // O(n) — avoid in loops
Use when: default key-value map. Prefer FrozenDictionary for build-once-read-many, ConcurrentDictionary for multi-threaded mutation.
SortedSet<T>
Red-black tree maintaining elements in sorted order with uniqueness. All ops O(log n). Iteration always yields elements in ascending order. Unique GetViewBetween for range queries.
O(log n) all ops Sorted + Unique
C#
SortedSet<int> ss = [5, 3, 8, 1, 9];  // stored as {1,3,5,8,9}
int min = ss.Min;                       // 1  — O(log n)
int max = ss.Max;                       // 9  — O(log n)

// Range view — unique to SortedSet
SortedSet<int> range = ss.GetViewBetween(3, 8); // {3,5,8}
SortedDictionary<K,V>
Dictionary backed by a red-black tree, keeping all key-value pairs sorted by key at all times. All operations O(log n). More memory than SortedList but O(log n) insert/remove vs O(n).
O(log n) all ops Sorted Keys
C#
SortedDictionary<string, int> sd = new()
{
    ["delta"] = 4, ["alpha"] = 1, ["gamma"] = 3
};
// Iteration: alpha=1, delta=4, gamma=3 (sorted)
foreach ((string k, int v) in sd)
    Console.WriteLine($"{k}={v}");
Queue<T>
First-in, first-out (FIFO) data structure backed by a circular array. Enqueue and Dequeue are both amortized O(1). Canonical data structure for BFS and task scheduling.
O(1) Enqueue/Dequeue FIFO
C#
Queue<int> q = [];
q.Enqueue(1); q.Enqueue(2); q.Enqueue(3);

int front  = q.Peek();    // 1 — look without removing
int first  = q.Dequeue(); // 1 — remove from front

// Safe variants
if (q.TryDequeue(out int val)) { ... }
if (q.TryPeek(out int peek))  { ... }
Stack<T>
Last-in, first-out (LIFO) structure backed by a dynamically-resized array. Push and Pop are amortized O(1). Used for DFS, expression parsing, undo/redo, and call-stack simulation.
O(1) Push/Pop LIFO
C#
Stack<string> stack = ["a", "b", "c"];  // top = "c"
string top    = stack.Peek();  // "c" — no removal
string popped = stack.Pop();   // "c" removed

// Iteration goes top-to-bottom
foreach (string s in stack)
    Console.Write(s + " ");  // "b" "a"
LinkedList<T>
Doubly linked list where each element is a LinkedListNode<T>. O(1) insertions and removals at any known node. No random access by index — traversal is O(n). Excel as deque or LRU cache backbone.
O(1) at-node ops O(n) index access
C#
LinkedList<int> ll = new();

LinkedListNode<int> nodeA = ll.AddLast(10);
LinkedListNode<int> nodeB = ll.AddFirst(5);
ll.AddAfter(nodeA, 15);         // 5 ↔ 10 ↔ 15
ll.Remove(nodeA);               // O(1) with node ref
ll.RemoveFirst();                // O(1)
ll.RemoveLast();                 // O(1)
VS IntelliSense Tip: AddLast() returns LinkedListNode<T> — save this if you need O(1) removal later. Discarding it forces O(n) search via Remove(value).
ImmutableArray<T>
Value-type wrapper around a fixed array providing immutability. A struct — zero overhead for empty instances. Mutation ops return a new ImmutableArray. More cache-friendly than ImmutableList.
Immutable O(1) index
C#
ImmutableArray<int> arr = [1, 2, 3];         // C# 12
ImmutableArray<int> arr2 = ImmutableArray.Create(1, 2, 3);

// "Mutation" — always capture return value!
ImmutableArray<int> added = arr.Add(4);    // arr unchanged
arr.Add(5);  // ❌ silently does nothing — discard
arr = arr.Add(5);  // ✅ reassign
ImmutableList<T>
Immutable ordered list backed by an AVL tree. O(log n) structural changes via structural sharing. Note: random indexing is O(log n), NOT O(1) — a hidden performance trap.
Immutable O(log n) index!
C#
// Builder pattern — batch construction is O(n) vs O(n log n)
var builder = ImmutableList.CreateBuilder<int>();
builder.Add(1); builder.Add(2); builder.Add(3);
ImmutableList<int> list = builder.ToImmutable();

// C# 12 collection expression
ImmutableList<int> list2 = [1, 2, 3];

// ⚠️  list[i] is O(log n) — avoid in tight loops
foreach (var item in list)  // O(n) total — preferred
    Console.Write(item);
ImmutableDictionary<K,V>
Immutable hash map backed by a hash-array-mapped trie (HAMT). O(log n) for all ops with structural sharing. For lookup-heavy fixed maps, FrozenDictionary is significantly faster.
Immutable O(log n) lookup
C#
ImmutableDictionary<string, int> d =
    ImmutableDictionary<string, int>.Empty
        .Add("x", 10).Add("y", 20);

// From Dictionary (builder pattern more efficient for bulk)
ImmutableDictionary<string, int> d2 =
    mutable.ToImmutableDictionary();

// "Mutation" returns new dict
ImmutableDictionary<string, int> d3 = d.SetItem("x", 99);
ImmutableHashSet<T>
Immutable set backed by HAMT trie. O(log n) membership testing. All mutation ops return new sets. Immutable counterpart to HashSet<T>.
Immutable O(log n) ops
C#
ImmutableHashSet<int> set = [1, 2, 3, 4];
ImmutableHashSet<int> s2  = set.Add(5);
ImmutableHashSet<int> s3  = set.Remove(2);

ImmutableHashSet<int> other = [3, 4, 5];
ImmutableHashSet<int> union = set.Union(other);
ImmutableHashSet<int> intersect = set.Intersect(other);
FrozenDictionary<K,V> .NET 8+
Read-only dictionary optimized for lookup performance after construction. Analyzes key set at build time to select perfect hash or SIMD strategies. 2x–5x faster lookup than Dictionary for string keys.
~O(1) optimized lookup Thread-safe
C#
using System.Collections.Frozen;

// Build once at startup — construction is ~20x slower than Dictionary
private static readonly FrozenDictionary<string, string> Routes =
    new Dictionary<string, string>
    {
        ["GET"]    = "HandleGet",
        ["POST"]   = "HandlePost",
        ["DELETE"] = "HandleDelete"
    }.ToFrozenDictionary(StringComparer.OrdinalIgnoreCase);

// Read many millions of times — same API as Dictionary
if (Routes.TryGetValue("get", out string? handler))
    Console.WriteLine(handler);  // "HandleGet"

// No .Add() or index setter — completely read-only
Use when: routing tables, keyword maps, config lookups — anything built once at startup and read in hot paths millions of times.
ConcurrentDictionary<K,V>
Thread-safe dictionary using fine-grained locking (per-bucket stripes). Atomic GetOrAdd, AddOrUpdate, and TryUpdate methods eliminate common race conditions.
Thread-safe O(1) amort
C#
ConcurrentDictionary<string, int> counts = new();

// Atomic add-or-get
int val = counts.GetOrAdd("key", 0);

// Atomic update — factory called only if key exists
counts.AddOrUpdate(
    key:                  "key",
    addValue:              1,
    updateValueFactory:   (k, old) => old + 1
);

// Compare-and-swap
bool updated = counts.TryUpdate("key", newValue: 99, comparisonValue: 1);
Channel<T>
High-performance async producer-consumer pipe in System.Threading.Channels. Supports backpressure, bounded/unbounded modes, and integrates natively with async/await and IAsyncEnumerable.
Thread-safe Async
C#
// Bounded — blocks on write when full
Channel<int> ch = Channel.CreateBounded<int>(capacity: 100);

// Producer
async Task ProduceAsync(CancellationToken ct)
{
    for (int i = 0; i < 100; i++)
        await ch.Writer.WriteAsync(i, ct);
    ch.Writer.Complete();
}

// Consumer — IAsyncEnumerable iteration
await foreach (int item in ch.Reader.ReadAllAsync(ct))
    Console.WriteLine(item);
Span<T>
Ref struct providing a type-safe, bounds-checked view over contiguous memory. Zero-copy and allocation-free. Cannot cross await boundaries, be stored in fields, or captured in lambdas.
Zero allocation Sync only
C#
// From array — zero-copy view
int[]      arr  = [1, 2, 3, 4, 5];
Span<int>  sp   = arr;
Span<int>  sp2  = arr.AsSpan(1, 3);     // [2,3,4]

// Stack allocation — zero heap
Span<int>  sp3  = stackalloc int[] { 1, 2, 3 };

// C# 12 collection expression
Span<int>  sp4  = [1, 2, 3];

// SIMD-friendly bulk ops
sp.Fill(0);                       // vectorized
sp.Sort();
bool eq = sp.SequenceEqual(sp2);

// Ref iteration for in-place mutation
foreach (ref int x in sp)
    x *= 2;
ReadOnlySpan<T>
Immutable counterpart of Span<T>. Same ref struct constraints apply. String literals and the string.AsSpan() method return ReadOnlySpan<char> — the foundation of zero-alloc string parsing.
Zero allocation Read-only
C#
// Zero-alloc string view
ReadOnlySpan<char> text  = "Hello, World!".AsSpan();
ReadOnlySpan<char> hello = text[..5];       // "Hello" — zero copy
bool starts = text.StartsWith("Hello");   // true

// Tokenization — zero allocation
foreach (Range r in text.Split(','))
{
    ReadOnlySpan<char> token = text[r];
    Console.WriteLine(token.ToString());  // only allocate here
}

// Inline from literal — stored in read-only data section
ReadOnlySpan<byte> png = [0x89, 0x50, 0x4E, 0x47];
Memory<T>
Heap-storable counterpart to Span<T>. Regular struct (not ref struct) — can be stored in fields, passed through async methods, and captured in lambdas. Extract Span synchronously via .Span property.
Async-safe Heap storable
C#
Memory<int> mem = arr.AsMemory();
Memory<int> sl  = mem.Slice(2, 4);     // zero-copy slice

// Async-compatible: can pass across await
async Task ProcessAsync(Memory<int> data)
{
    await Task.Delay(1);          // data survives await
    Span<int> s = data.Span;        // extract synchronously
}

// Pool pattern — rent → process → return
using IMemoryOwner<int> owner = MemoryPool<int>.Shared.Rent(64);
Memory<int> rented = owner.Memory;

Section 04

Practical Patterns

4.1 Duplicate Detection

C#
static bool HasDuplicate<T>(IEnumerable<T> source)
{
    HashSet<T> seen = [];
    foreach (T item in source)
        if (!seen.Add(item))  // false = already present
            return true;
    return false;
}

static T? FirstDuplicate<T>(IEnumerable<T> source)
{
    HashSet<T> seen = [];
    foreach (T item in source)
        if (!seen.Add(item))
            return item;
    return default;
}

4.2 Frequency Counting with CollectionsMarshal

C# — Single-Lookup Increment
static Dictionary<T, int> CountFrequencies<T>(IEnumerable<T> source)
    where T : notnull
{
    Dictionary<T, int> freq = [];

    foreach (T item in source)
    {
        // ONE hash lookup — GetValueRefOrAddDefault finds or creates the slot
        ref int count = ref CollectionsMarshal.GetValueRefOrAddDefault(
            freq, item, out bool exists);
        count++;  // works for new (0→1) and existing (n→n+1)
    }

    return freq;
}

4.3 Config/INI Parsing — Zero-Alloc ReadOnlySpan

C# — Zero-Alloc Tokenisation
static Dictionary<string, Dictionary<string, string>> ParseIni(ReadOnlySpan<char> content)
{
    Dictionary<string, Dictionary<string, string>> result = [];
    string section = string.Empty;
    result[section] = [];

    foreach (Range lineRange in content.Split('\n'))
    {
        ReadOnlySpan<char> line = content[lineRange].Trim();
        if (line.IsEmpty || line[0] == ';') continue;

        if (line[0] == '[')
        {
            int close = line.IndexOf(']');
            if (close > 1)
            {
                section = line[1..close].ToString();   // allocate only here
                result.TryAdd(section, []);
            }
            continue;
        }

        int eq = line.IndexOf('=');
        if (eq <= 0) continue;

        ReadOnlySpan<char> key   = line[..eq].Trim();
        ReadOnlySpan<char> value = line[(eq + 1)..].Trim();
        if (!key.IsEmpty)
            result[section][key.ToString()] = value.ToString();  // alloc only at storage
    }

    return result;
}

4.4 Two-Pointer Pattern with T[]

C#
static (int left, int right) TwoSumSorted(int[] nums, int target)
{
    int left = 0, right = nums.Length - 1;
    while (left < right)
    {
        int sum = nums[left] + nums[right];
        if      (sum == target) return (left, right);
        else if (sum < target)  left++;
        else                    right--;
    }
    return (-1, -1);
}

// Remove duplicates from sorted array in-place — O(n), O(1)
static int RemoveDuplicates(int[] nums)
{
    int slow = 0;
    for (int fast = 1; fast < nums.Length; fast++)
        if (nums[fast] != nums[slow])
            nums[++slow] = nums[fast];
    return slow + 1;
}

4.5 Sliding Window — LinkedList as Monotonic Deque

C# — Sliding Window Maximum
// LinkedList gives O(1) remove from BOTH ends — Queue only allows front removal
static int[] SlidingWindowMaximum(int[] nums, int k)
{
    int[]             result = new int[nums.Length - k + 1];
    LinkedList<int> deque  = [];  // stores indices, front = max index
    int ri = 0;

    for (int i = 0; i < nums.Length; i++)
    {
        // Evict indices outside window
        if (deque.Count > 0 && deque.First!.Value < i - k + 1)
            deque.RemoveFirst();  // O(1)

        // Maintain decreasing order — remove smaller candidates from back
        while (deque.Count > 0 && nums[deque.Last!.Value] < nums[i])
            deque.RemoveLast();   // O(1) — why LinkedList beats Queue here

        deque.AddLast(i);

        if (i >= k - 1)
            result[ri++] = nums[deque.First!.Value];
    }
    return result;
}

4.6 Graph Adjacency — Dictionary<int, List<int>>

C#
sealed class Graph
{
    private readonly Dictionary<int, List<int>> _adj = [];

    public void AddEdge(int u, int v)
    {
        if (!_adj.TryGetValue(u, out List<int>? neighbors))
            _adj[u] = neighbors = [];
        neighbors.Add(v);
        _adj.TryAdd(v, []);
    }

    public List<int> BFS(int src)
    {
        List<int>    visited = [];
        HashSet<int> seen    = [src];
        Queue<int>   queue   = [src];

        while (queue.Count > 0)
        {
            int cur = queue.Dequeue();
            visited.Add(cur);
            foreach (int nb in _adj.GetValueOrDefault(cur, []))
                if (seen.Add(nb))
                    queue.Enqueue(nb);
        }
        return visited;
    }
}

4.7 Memoisation Cache Pattern

C# — Generic Memoize Wrapper
static Func<TIn, TOut> Memoize<TIn, TOut>(Func<TIn, TOut> func)
    where TIn : notnull
{
    Dictionary<TIn, TOut> cache = [];
    return input =>
    {
        if (cache.TryGetValue(input, out TOut? cached))
            return cached;
        TOut result = func(input);
        cache[input] = result;
        return result;
    };
}

// Fibonacci with recursive memo lambda
static long Fibonacci(int n)
{
    Dictionary<int, long> memo = [];
    Func<int, long>? fib = null;
    fib = k => k <= 1 ? k
        : memo.TryGetValue(k, out long c) ? c
        : memo[k] = fib!(k-1) + fib!(k-2);
    return fib(n);
}

01
Two Sum
Dictionary<int, int>

Given array nums and target, return indices of two numbers that sum to target.

Why Dictionary: As we iterate, for each nums[i] we compute complement = target - nums[i] and check if it's in the map. O(1) lookup per element vs O(n) for array scan. HashSet alone would give membership but not the original index — we need the index as the value.

Time
O(n)
Space
O(n)
Passes
Single
C# Solution
public int[] TwoSum(int[] nums, int target)
{
    Dictionary<int, int> seen = new(capacity: nums.Length);

    for (int i = 0; i < nums.Length; i++)
    {
        int complement = target - nums[i];

        // O(1) — was complement seen in a previous iteration?
        if (seen.TryGetValue(complement, out int ci))
            return [ci, i];

        // Store current number AFTER checking (prevents using same index twice)
        seen[nums[i]] = i;
    }
    return [-1, -1];  // unreachable per problem guarantee
}

03
Number of Islands
Queue<(int,int)> BFS

Given a binary grid, count the number of islands (connected '1' regions).

Why Queue: BFS order ensures we fully explore each island before moving to the next. Value tuples (int row, int col) avoid heap allocation per element. bool[,] visited gives O(1) membership test per cell.

Time
O(m × n)
Space
O(m × n)
C#
private static readonly (int dr, int dc)[] Dirs = [(-1,0),(1,0),(0,-1),(0,1)];

public int NumIslands(char[][] grid)
{
    int rows = grid.Length, cols = grid[0].Length, count = 0;
    bool[,] visited = new bool[rows, cols];

    for (int r = 0; r < rows; r++)
    for (int c = 0; c < cols; c++)
        if (grid[r][c] == '1' && !visited[r, c])
        {
            count++;
            Queue<(int, int)> q = [(r, c)];
            visited[r, c] = true;

            while (q.Count > 0)
            {
                (int cr, int cc) = q.Dequeue();
                foreach ((int dr, int dc) in Dirs)
                {
                    int nr = cr+dr, nc = cc+dc;
                    if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
                    if (visited[nr,nc] || grid[nr][nc] != '1') continue;
                    visited[nr, nc] = true;
                    q.Enqueue((nr, nc));
                }
            }
        }
    return count;
}
04
Top K Frequent Elements
Dictionary + List[] Bucket Sort

Return the k most frequent elements from an array.

Why List[]: Bucket sort — array of lists indexed by frequency (1..n). Avoids O(n log n) sort; O(n) construction + O(n) collection = O(n) total.

Time
O(n)
Space
O(n)
C#
public int[] TopKFrequent(int[] nums, int k)
{
    Dictionary<int, int> freq = new(capacity: nums.Length);
    foreach (int n in nums)
    {
        ref int c = ref CollectionsMarshal.GetValueRefOrAddDefault(freq, n, out _);
        c++;
    }

    // Bucket: index = frequency, value = nums with that frequency
    List<int>[] buckets = new List<int>[nums.Length + 1];
    foreach ((int num, int frequency) in freq)
    {
        buckets[frequency] ??= [];
        buckets[frequency].Add(num);
    }

    List<int> result = new(capacity: k);
    for (int f = buckets.Length - 1; f >= 1 && result.Count < k; f--)
    {
        if (buckets[f] is null) continue;
        foreach (int num in buckets[f])
        {
            result.Add(num);
            if (result.Count == k) break;
        }
    }
    return [..result];
}
05
LRU Cache
LinkedList + Dictionary<int, LinkedListNode>

Design a data structure with O(1) Get and Put using LRU eviction policy.

Why LinkedList + Dictionary: LinkedList maintains usage order (head=MRU, tail=LRU) with O(1) node operations. Dictionary maps each key to its node for O(1) access. Together: O(1) Get (lookup + move-to-front) and O(1) Put (insert + optional tail eviction).

Get
O(1)
Put
O(1)
Space
O(capacity)
C#
public class LRUCache
{
    private readonly int                                            _capacity;
    private readonly LinkedList<(int key, int val)>             _list;
    private readonly Dictionary<int, LinkedListNode<(int, int)>> _map;

    public LRUCache(int capacity)
    {
        _capacity = capacity;
        _list = new();
        _map  = new(capacity);
    }

    public int Get(int key)
    {
        if (!_map.TryGetValue(key, out var node)) return -1;
        MoveToFront(node);
        return node.Value.val;
    }

    public void Put(int key, int value)
    {
        if (_map.TryGetValue(key, out var existing))
        {
            _list.Remove(existing);
            _map[key] = _list.AddFirst((key, value));
        }
        else
        {
            if (_list.Count == _capacity && _list.Last is { } lru)
            {
                _map.Remove(lru.Value.key);
                _list.RemoveLast();
            }
            _map[key] = _list.AddFirst((key, value));
        }
    }

    private void MoveToFront(LinkedListNode<(int, int)> node)
    {
        if (node == _list.First) return;
        _list.Remove(node);    // O(1) — have direct node reference
        _list.AddFirst(node);  // O(1)
    }
}

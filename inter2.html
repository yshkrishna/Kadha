Q1
Run-Length Encoding (String Compression)
DSA 🔥 VERY COMMON
▼
📖 The Problem
Problem
Input: aaabbcccceeaa
Output: a3b2c4e2a2
🎯 Analogy — Understand It Simply
📦
Imagine you're packing boxes. Instead of writing "apple, apple, apple" you write "apple × 3". That's exactly what run-length encoding does — it counts consecutive identical characters and writes them as character + count.
🧠 Algorithm — Step by Step
1
Start at index 0, set count = 1
2
Compare current char with next char. If same → increment count. If different → append char+count to result, reset count to 1.
3
After loop ends, don't forget to append the last character group!
4
Return the result string.
🔬 Dry Run — aaabbcccceeaa
IndexCharNextCountActionResult So Far
0aa1→2same, count++""
1aa2→3same, count++""
2ab3diff → write a3"a3"
3bb1→2same, count++"a3"
4bc2diff → write b2"a3b2"
5-8c×4e4diff → write c4"a3b2c4"
9-10e×2a2diff → write e2"a3b2c4e2"
11-12a×2END2loop ends → write a2"a3b2c4e2a2" ✅
💻 Solution Code (C#)
public static string RunLengthEncode(string input)
{
    if (string.IsNullOrEmpty(input)) return "";

    var result = new StringBuilder();
    int count = 1;

    for (int i = 1; i < input.Length; i++)
    {
        if (input[i] == input[i - 1])
            count++;
        else
        {
            result.Append(input[i - 1]);
            result.Append(count);
            count = 1;
        }
    }
    // Don't forget the last group!
    result.Append(input[input.Length - 1]);
    result.Append(count);

    return result.ToString();
}
⚡ Complexity
Time
O(n)
Space
O(n)
Single Pass
✅ Yes
⚠️ Common Mistakes
1. Forgetting to append the LAST group after the loop ends.
2. Using string += inside loops (creates new strings each time — O(n²)). Always use StringBuilder!
🎤 Interview Tips
• Mention StringBuilder vs string concatenation proactively.
• Discuss edge cases: empty string, single char, all same chars.
• Extension: what if count=1? Should you write "a1" or just "a"?
⚡ Quick Summary

Scan string once. Count consecutive same chars. On change → write char+count. Don't miss the last group. Use StringBuilder for O(n) space efficiency.

Q2
Remove Duplicates from Array
DSA 🔥 VERY COMMON
▼
🎯 Analogy
📋
Imagine a guest list with duplicate names. You want to keep only the first occurrence of each name and hand a clean list. You'd go through the list, and tick off names you've already seen.
🧠 Three Approaches
Approach 1 — Using HashSet (Best)
A HashSet automatically rejects duplicates. Loop through array, try to add each element — HashSet ignores it if already present.
Approach 2 — Using LINQ (Cleanest Code)
array.Distinct().ToArray() — clean one-liner but hides the logic.
Approach 3 — Nested Loop (Naive — Avoid!)
O(n²) — for each element, scan all previous elements. Too slow for large arrays.
💻 Solution Code (C#)
// Approach 1: HashSet — O(n) time, O(n) space
public static int[] RemoveDuplicates(int[] arr)
{
    var seen = new HashSet<int>();
    var result = new List<int>();

    foreach (var num in arr)
    {
        if (seen.Add(num))  // Add returns false if duplicate
            result.Add(num);
    }
    return result.ToArray();
}

// Approach 2: LINQ (clean but for interviews, explain it)
var unique = arr.Distinct().ToArray();

// Input:  [1, 2, 3, 1, 2, 4, 5]
// Output: [1, 2, 3, 4, 5]

SOLID Principles — What's Wrong with ReportGenerator?
OOP SOLID 🔥 VERY COMMON
▼
🎯 What is SOLID?
🏗️
SOLID is like building rules for software. Just as a good building has one purpose per room (kitchen = cooking, bedroom = sleeping), SOLID says each class should have one purpose, and adding new features shouldn't break old ones.
🔍 Problems in ReportGenerator
❌ Violation 1 — SRP (Single Responsibility Principle)
Problem: One class is doing 3 completely different jobs: generating reports, saving files, and sending emails.

Rule: A class should have only ONE reason to change.
Real-world: A chef cooks. A waiter serves. They don't swap jobs.
❌ Violation 2 — OCP (Open/Closed Principle)
Problem: The GenerateReport method uses if/else if to check report types. To add "Word" format, you MUST edit this method.

Rule: Classes should be Open for extension, Closed for modification.
Real-world: A power strip has sockets — you add new devices without rebuilding it.
✅ Fixed Design — Applying SOLID
// SRP: Separate concerns into separate classes

// OCP: Use abstraction so new types can be added
public interface IReportGenerator
{
    void Generate();
}

public class PdfReportGenerator : IReportGenerator
{
    public void Generate() => Console.WriteLine("Generating PDF...");
}

public class ExcelReportGenerator : IReportGenerator
{
    public void Generate() => Console.WriteLine("Generating Excel...");
}

// SRP: File saving is separate
public class FileSaver
{
    public void Save(string data) => File.WriteAllText("report.txt", data);
}

// SRP: Email sending is separate
public class EmailSender
{
    public void Send(string email, string content)
        => Console.WriteLine($"Sending to {email}");
}

// Adding "Word" format? Just add a new class — no existing code changes!
public class WordReportGenerator : IReportGenerator
{
    public void Generate() => Console.WriteLine("Generating Word...");
}

Q4
Async/Await — How Long Does Each Take?
ASYNC 🔥 TRICKY
▼
🎯 Analogy — The Restaurant Kitchen
🍳
Sequential await = One chef does task1, waits for it to finish, then does task2. Tasks run one at a time.

Task.WhenAll = Three chefs cook simultaneously. All start at once, you wait for the slowest one.

Fire-and-forget = You started 3 chefs but left the kitchen before they finished!
📊 Time Analysis (Assume each task = 1 second)
MethodHow it runsTotal Time
doAsyncTask() with sequential await1s → wait → 1s → wait → 1s~3 seconds
NormalTask() synchronous1s + 1s + 1s (blocking)~3 seconds
doAsyncTask() fire-and-forget ⚠️Tasks START but aren't awaited~0 seconds (BUG!)
🔍 Detailed Breakdown
Version 1 — Sequential await (3 seconds)
Each await pauses execution until that task completes. Like waiting at a red light, then driving, then another red light. Total = sum of all tasks.
Version 2 — Normal synchronous (3 seconds)
Blocking calls. Thread is occupied the whole time. Same time as sequential await, but BLOCKS the thread (no UI responsiveness, no other work).
Version 3 — Fire and Forget (DANGEROUS — ~0 seconds recorded but tasks incomplete)
Tasks are started but not awaited. Timer stops immediately. Tasks still run in background. Exceptions are SWALLOWED silently! This is a common bug.
✅ The RIGHT Way — Parallel Execution (Fastest)
public async Task DoParallelAsync()
{
    // Start all tasks FIRST (don't await yet)
    Task t1 = TaskAsync1();  // starts immediately
    Task t2 = TaskAsync2();  // starts immediately
    Task t3 = TaskAsync3();  // starts immediately

    // NOW await all of them together
    await Task.WhenAll(t1, t2, t3);

    // Total time = MAX of all tasks, not SUM!
    // If each = 1 sec → total ~1 second ✅
}
🗺️ Visual: Sequential vs Parallel
Sequential await: ───[Task1: 1s]──►───[Task2: 1s]──►───[Task3: 1s]──► Total: 3s Parallel (WhenAll): ───[Task1: 1s]──► ───[Task2: 1s]──► All running simultaneously! ───[Task3: 1s]──► Total: ~1s ✅ Fire-and-forget: ───[Task1]─ (not awaited) ───[Task2]─ (not awaited) Timer stops here ⚠️ ───[Task3]─ (not awaited)
⚡ Quick Summary

Sequential await = 3s. Sync = 3s but blocks thread. Fire-and-forget = BUGS (exceptions lost, tasks untracked). Use Task.WhenAll() for parallel = 1s!

Q5
Move All Zeroes to End (Keep Order)
DSA 🔥 CLASSIC
▼
🎯 Analogy
🧹
Think of sweeping a floor. Non-zero elements are people standing, zeroes are dust. You move everyone to the left, and the dust naturally settles to the right. People keep their relative order!
🧠 Two Pointer Algorithm
1
writePos = 0 — this pointer marks where the next non-zero goes.
2
Loop through array. When we find a non-zero element, place it at arr[writePos] and increment writePos.
3
After loop: Fill remaining positions from writePos to end with 0s.
🔬 Dry Run — [0, 1, 0, 3, 12]
iarr[i]ActionArray StatewritePos
00Skip (zero)[0,1,0,3,12]0
11Place at [0][1,1,0,3,12]1
20Skip (zero)[1,1,0,3,12]1
33Place at [1][1,3,0,3,12]2
412Place at [2][1,3,12,3,12]3
——Fill [3],[4] with 0[1,3,12,0,0] ✅3
💻 Solution Code (C#)
public static void MoveZeroesEnd(int[] arr)
{
    int writePos = 0;

    // Step 1: Copy all non-zeros to front
    foreach (var num in arr)
    {
        if (num != 0)
            arr[writePos++] = num;
    }

    // Step 2: Fill rest with zeros
    while (writePos < arr.Length)
        arr[writePos++] = 0;
}

// Input:  [0, 1, 0, 3, 12]
// Output: [1, 3, 12, 0, 0]
⚡ Complexity
Time
O(n)
Space
O(1)
In-place
✅ Yes
⚡ Quick Summary

Two-pointer technique. One pass to move non-zeros to front (preserving order), then fill tail with zeros. O(n) time, O(1) space — in-place!

Q6
Implement LRU Cache
DSA System Design 🔥 TOP INTERVIEW Q
▼
🎯 What is LRU Cache?
📚
Imagine a small bookshelf holding 3 books. When it's full and you need a new book, you remove the one you read least recently. The most recently used books stay near the front. That's LRU (Least Recently Used) caching!

Real examples: Browser cache, CPU cache, Redis cache, OS page replacement.
🧠 Data Structure Design
Why Dictionary + LinkedList?
• Dictionary (HashMap): O(1) lookup by key
• LinkedList: O(1) add/remove from front and back
• Together: Get = O(1), Put = O(1) ← both operations are constant time!
Most Recently Used Least Recently Used │ │ ▼ ▼ [HEAD] ←→ [Node:A,1] ←→ [Node:B,2] ←→ [TAIL] Dictionary: { "A" → NodeA, "B" → NodeB } On GET(A): Move A to front (most recent) On PUT(new) when full: Remove from TAIL (least recent)
💻 LRU Cache Implementation (C#)
public class LRUCache
{
    private readonly int _capacity;
    private readonly Dictionary<int, LinkedListNode<(int key, int val)>> _map;
    private readonly LinkedList<(int key, int val)> _list;

    public LRUCache(int capacity)
    {
        _capacity = capacity;
        _map = new();
        _list = new();
    }

    public int Get(int key)
    {
        if (!_map.ContainsKey(key)) return -1;

        var node = _map[key];
        _list.Remove(node);          // Remove from current position
        _list.AddFirst(node.Value);   // Move to front (most recent)
        _map[key] = _list.First!;

        return node.Value.val;
    }

    public void Put(int key, int value)
    {
        if (_map.ContainsKey(key))
        {
            _list.Remove(_map[key]);   // Remove old position
        }
        else if (_map.Count == _capacity)
        {
            // Evict least recently used (tail)
            var lru = _list.Last!;
            _map.Remove(lru.Value.key);
            _list.RemoveLast();
        }

        _list.AddFirst((key, value));  // Add to front
        _map[key] = _list.First!;
    }
}
⚡ Complexity
Get Time
O(1)
Put Time
O(1)
Space
O(n)
⚡ Quick Summary

LRU Cache = Dictionary + DoublyLinkedList. Dictionary for O(1) lookups. LinkedList for O(1) ordering (most recent = head, LRU = tail). On capacity: evict tail. On access/write: move to head.

Q8
Extension Methods — Add GetData() to Employee Without Changing It
C# Feature 🔥 COMMON
▼
🎯 Analogy
🔧
Imagine a tool you bought that doesn't have a specific attachment. Instead of rebuilding the tool, you create an adapter/attachment that works WITH the tool. That's what Extension Methods do — they add new methods to existing classes without modifying them!

This is also how LINQ works! .Where(), .Select() etc. are all extension methods on IEnumerable.
📋 Rules for Extension Methods
4 Requirements
1. Must be in a static class
2. Method must be static
3. First parameter: this ClassName param (the "this" keyword is the magic!)
4. Call it like a normal instance method
💻 Solution Code (C#)
// The DLL has this class — we CANNOT change it
public class Employee
{
    public int Id { get; set; }
    public string Name { get; set; }
}

// OUR code — adding GetData without modifying Employee
public static class EmployeeExtensions
{
    // "this Employee emp" = this applies to Employee instances
    public static string GetData(this Employee emp)
    {
        return $"ID: {emp.Id}, Name: {emp.Name}";
    }

    // You can add as many extension methods as needed!
    public static bool IsValid(this Employee emp)
    {
        return emp.Id > 0 && !string.IsNullOrEmpty(emp.Name);
    }
}

// Usage — looks like Employee has these methods natively!
var emp = new Employee { Id = 1, Name = "Alice" };
var data = emp.GetData();   // "ID: 1, Name: Alice"
bool valid = emp.IsValid(); // true
⚠️ Limitations of Extension Methods
• Cannot access private members of the class
• Won't show in IntelliSense unless the static class namespace is imported
• If the class adds a method with same name later, the original method takes priority
⚡ Quick Summary

Extension methods = add methods to sealed/external classes without inheritance or modification. Static class + static method + "this TypeName param". This is how LINQ is built!

💻 SQL Solution
-- Solution using subquery
SELECT
    city,
    COUNT(customer_id) AS customer_count
FROM
    customers
GROUP BY
    city
HAVING
    COUNT(customer_id) > (
        -- Subquery: average customers per city
        SELECT AVG(city_count)
        FROM (
            SELECT COUNT(customer_id) AS city_count
            FROM customers
            GROUP BY city
        ) AS city_totals
    )
ORDER BY customer_count DESC;

-- Result:
-- city     | customer_count
-- ---------+--------------
-- New York  | 2
-- London    | 2

FizzBuzz Variant — Output "a", "b", "ab"
DSA 🔥 CLASSIC TRAP
▼
📋 Pattern Analysis
Input: [1..20] — Find the Rule
Look at the output: [1,2,"a",4,"b","a",7,8,"a","b",11,"a",13,14,"ab",16,17,"a",19,"b"]
PositionValueDivisible by?Rule
3"a"3div by 3 → "a"
5"b"5div by 5 → "b"
6"a"3div by 3 → "a"
9"a"3div by 3 → "a"
10"b"5div by 5 → "b"
12"a"3div by 3 → "a"
15"ab"3 AND 5div by BOTH → "ab"
18"a"3div by 3 → "a"
20"b"5div by 5 → "b"
🧠 Key Insight — Check "ab" FIRST!
⚠️ Common Mistake
Don't use else if! If you check % 3 first with else if, number 15 will match 3 and skip 5. Always build the string or check both conditions independently!
💻 Solution Code (C#)
var numbers = Enumerable.Range(1, 20);
var result = new List<object>();

foreach (var i in numbers)
{
    string output = "";

    if (i % 3 == 0) output += "a";  // Divisible by 3
    if (i % 5 == 0) output += "b";  // Divisible by 5 (separate if!)

    result.Add(output.Length > 0 ? output : (object)i);
}

// Output: [1, 2, "a", 4, "b", "a", 7, 8, "a", "b", 11, "a", 13, 14, "ab", ...]

// LINQ version (one-liner)
var out2 = Enumerable.Range(1, 20)
    .Select(i =>
    {
        string s = (i % 3 == 0 ? "a" : "") + (i % 5 == 0 ? "b" : "");
        return s.Length > 0 ? (object)s : i;
    })
    .ToList();
⚡ Quick Summary

This is FizzBuzz with custom labels. Key trick: use two separate if statements (not else-if) so both conditions can fire. Concatenate "a" and "b" to naturally get "ab" for multiples of 15.

Q12
Design Elevator System — Class Design
System Design OOP 🔥 TOP INTERVIEW Q
▼
🎯 Requirements
System Spec
• 3 Elevators
• 25-floor building
• Each elevator has: current floor, direction, status, capacity
• Building controls which elevator to dispatch
🏗️ System Architecture
┌─────────────────────────────────────────────────┐ │ Building │ │ ┌─────────────────────────────────────────┐ │ │ │ ElevatorController │ │ │ │ - Dispatch(requestedFloor) │ │ │ │ - FindNearestElevator() │ │ │ └─────────────────────────────────────────┘ │ │ │ │ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ │ │Elevator 1│ │Elevator 2│ │Elevator 3│ │ │ │Floor: 3 │ │Floor: 10 │ │Floor: 20 │ │ │ │Dir: UP │ │Dir: IDLE │ │Dir: DOWN │ │ │ └──────────┘ └──────────┘ └──────────┘ │ │ │ │ Floor Buttons: [1][2][3]...[25] │ └─────────────────────────────────────────────────┘
💻 Class Definitions (C#)
// Enums for state
public enum Direction { Up, Down, Idle }
public enum ElevatorStatus { Moving, Stopped, OutOfService }

// Represents a floor button request
public class ElevatorRequest
{
    public int RequestedFloor { get; set; }
    public Direction Direction { get; set; }
}

// Core Elevator class
public class Elevator
{
    public int Id { get; }
    public int CurrentFloor { get; private set; }
    public Direction Direction { get; private set; }
    public ElevatorStatus Status { get; private set; }
    public int Capacity { get; } = 10;
    public int CurrentLoad { get; private set; }

    private Queue<int> _floorQueue = new();

    public Elevator(int id, int startFloor = 1)
    {
        Id = id;
        CurrentFloor = startFloor;
        Direction = Direction.Idle;
        Status = ElevatorStatus.Stopped;
    }

    public void AddFloorRequest(int floor)
    {
        _floorQueue.Enqueue(floor);
        MoveToNextFloor();
    }

    private void MoveToNextFloor()
    {
        if (!_floorQueue.Any()) { Direction = Direction.Idle; return; }

        int target = _floorQueue.Peek();
        Direction = target > CurrentFloor ? Direction.Up : Direction.Down;
        Status = ElevatorStatus.Moving;

        // Simulate movement (in real system: event-driven)
        CurrentFloor = _floorQueue.Dequeue();
        Status = ElevatorStatus.Stopped;
        MoveToNextFloor();
    }
}

// Dispatcher: picks the best elevator
public class ElevatorController
{
    private List<Elevator> _elevators;

    public ElevatorController(int count, int floors)
    {
        _elevators = Enumerable.Range(1, count)
            .Select(i => new Elevator(i))
            .ToList();
    }

    public void RequestElevator(int floor, Direction dir)
    {
        var best = _elevators
            .Where(e => e.Status != ElevatorStatus.OutOfService)
            .OrderBy(e => Math.Abs(e.CurrentFloor - floor))
            .First();  // Nearest available elevator

        best.AddFloorRequest(floor);
    }
}

// Building ties it all together
public class Building
{
    public int TotalFloors { get; } = 25;
    public ElevatorController Controller { get; }

    public Building() => Controller = new ElevatorController(3, 25);

How to Use This Roadmap
Work through each category in order — Arrays and Hashing build intuition for everything else.
1
Attempt independently — Spend 20–30 minutes on each problem before looking anything up. Struggle is where learning happens.
2
Read the hint, not the solution — If stuck, find only the pattern/approach hint. Preserve the "aha" moment.
3
Review complexity — After solving, document the time and space complexity explicitly before moving on.
4
Rewrite from scratch the next day — Active recall beats passive re-reading by 4×. Close your editor and rewrite without notes.
5
Write idiomatic C# — Use Dictionary<K,V>, PriorityQueue<T,P>, SortedSet<T> — interviewers expect BCL fluency.

Interview Tips for Beginners
What separates a good solution from a great interview performance.
🗣️
Talk Before You Type
Explain your thought process aloud before writing code. Interviewers evaluate reasoning, not just the final answer.
❓
Clarify Constraints First
Always ask about input size, edge cases (empty input, negatives, duplicates), and expected output format before starting.
🪜
Start With Brute Force
State the naive approach and its complexity, then optimize. Never jump to the clever solution without acknowledging it.
📖
Name Variables Clearly
Use names like left, right, windowSum, visited. Readable code signals professionalism to your interviewer.
🧪
Test With Edge Cases
Walk through with the given example, then test an edge case — empty array, single element, all same values — before declaring done.
⏱️
Always State Complexity
State Big-O time and space complexity before finishing your answer — even if the interviewer does not explicitly ask for it.

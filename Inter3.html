Merge Overlapping Intervals

DSAArrays · Sorting
📋 Problem

Input: [[1,3],[2,6],[8,10],[15,18]]

Output: [[1,6],[8,10],[15,18]]

Merge all intervals that overlap. Return the simplified list.

🧸 Playground Booking Analogy

Kids booking a slide: Kid A: 1–3pm, Kid B: 2–6pm — they overlap at 2pm and 3pm, so combine into 1–6pm. Kid C: 8–10pm — no overlap, stays alone.

Merging intervals = combining overlapping time bookings into one.

🗺️ Algorithm Steps

1
Sort by start time

Ensures overlapping intervals are adjacent. Without sorting, the algorithm breaks on unsorted input.

2
Take first as "current"

This is the interval we're trying to extend.

3
Check overlap: next.start ≤ current.end?

If yes — merge by extending current.end = Max(current.end, next.end).

4
No overlap → save current, move on

Add current to results. Next becomes the new current.

5
Add the final "current"

The loop ends without adding the last interval — do it manually.

💻 Complete C# Solution

C#
public static int[][] Merge(int[][] intervals)
{
    // ✅ Always sort first — candidate forgot this!
    Array.Sort(intervals, (a, b) => a[0].CompareTo(b[0]));

    var result  = new List<int[]>();
    int[] current = intervals[0];

    for (int i = 1; i < intervals.Length; i++)
    {
        int[] next = intervals[i];
        if (next[0] <= current[1])
            current[1] = Math.Max(current[1], next[1]);
        else { result.Add(current); current = next; }
    }
    result.Add(current);
    return result.ToArray();
}
⏱ Time: O(n log n)
💾 Space: O(n)
⚠️
Template Feedback: Candidate forgot to sort. Always sort first. Mention it proactively — shows senior awareness. Never assume sorted input.

📋 Problem — find per customer:

🧸 Toy Store Report Card Analogy

A toy store has a notebook of every purchase. The manager wants a report card per customer: how many visits, total spent, average per visit, biggest purchase, and who spent the most overall.

SQL aggregation = making that report card for groups of rows.

💻 The Complete SQL Query

SQL
SELECT
    customer_name,
    COUNT(order_id)              AS total_orders,
    SUM(order_amount)            AS total_amount,
    ROUND(AVG(order_amount), 2)   AS avg_amount,
    MAX(order_amount)            AS largest_order,
    RANK() OVER (
        ORDER BY SUM(order_amount) DESC
    )                            AS spend_rank
FROM   orders
GROUP BY customer_name
ORDER BY spend_rank;

🪟 Window Functions — What RANK() OVER Does

Regular aggregates collapse rows. Window functions add a new column without collapsing. The OVER(...) defines the frame of rows to operate on.


Part of RANK() OVERWhat it means
RANK()
The ranking functionAssigns a rank number. Tied values share the same rank. The rank after a tie jumps (1,1,3 — not 1,1,2).
OVER (...)
"Look at this window of rows"Required for all window functions. Defines the scope. Without OVER, RANK() is a syntax error.
ORDER BY SUM(order_amount) DESC
Rank by total spend, highest firstThe customer with the highest SUM gets rank 1. DESC = descending = biggest number = lowest rank number.

RANK vs DENSE_RANK vs ROW_NUMBER — know all three:

FunctionTies?Example scores: 1000, 1000, 700
ROW_NUMBER()No ties — always unique1, 2, 3
RANK()Ties share rank, next skips1, 1, 3 ← gap!
DENSE_RANK()Ties share rank, no gaps1, 1, 2 ← no gap
⚠️
Can't filter by RANK in WHERE SQL runs WHERE before SELECT (before window functions exist). Use a CTE: WITH r AS (SELECT ..., RANK() OVER(...) AS rk FROM ... GROUP BY ...) SELECT * FROM r WHERE rk <= 3
💡
SQL Execution Order — memorise this! FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. This is why you can't reference a SELECT alias in WHERE — WHERE runs before SELECT.

📋 Problem

Find the Top 2 customers who spent the most money. Each Order has a list of OrderItems. Each item has Quantity and Price. Total = Quantity × Price per item, summed across all items and all orders per customer.

🧸 Receipts in a Box Analogy

A box of receipts. Each receipt (Order) belongs to a customer and has several line items. To find who spent the most: add up each item (qty × price), total each receipt, group by customer, sum their receipts, sort, take top 2.

LINQ does exactly this — one clean chain of operations.

💻 Complete LINQ Solution

C# — LINQ
var topCustomers = orders
    .GroupBy(o => o.Customer)
    .Select(g => new
    {
        Customer   = g.Key,
        TotalSpend = g.Sum(o => o.Items.Sum(item => item.Quantity * item.Price))
    })
    .OrderByDescending(x => x.TotalSpend)
    .Take(2)
    .ToList();

foreach (var c in topCustomers)
    Console.WriteLine($"{c.Customer}: {c.TotalSpend:N0}");
// Alice:   81,000
// Charlie: 40,000

DSA — Merge Intervals

5 Questions
1
Algorithm design
How would you merge overlapping intervals? Walk me through your approach before writing any code.
▼
✅ Model Answer

First, I'd sort the intervals by their start time. Without sorting, overlapping intervals could be anywhere in the list, requiring O(n²) comparisons. Sorting ensures any overlapping intervals are adjacent, enabling a single O(n) pass.

Then I'd keep a "current" interval. For each next interval I check: does it start before (or at) the current end? If yes — overlap — extend current.end to Max(current.end, next.end). If no — no overlap — save current to results, and make next the new current.

After the loop, add the last current interval to results. Time: O(n log n) due to sorting. Space: O(n) for the result list.

2
Edge case
What happens with exactly adjacent intervals like [1,3] and [3,5]? Should they merge?
▼
✅ Model Answer

Yes — they merge into [1,5].

The overlap condition is next.start <= current.end. Since 3 ≤ 3 is true, they merge. This is correct: [1,3] and [3,5] share the point 3 and form a continuous range [1,5] with no gap.

If the problem says they should NOT merge, you'd use strict less-than: next.start < current.end. Always clarify this with the interviewer — it's a legitimate ambiguity worth calling out.

3
Complexity
What is the time and space complexity of your solution? Explain why.
▼
✅ Model Answer

Time: O(n log n) — dominated by sorting. Sorting n intervals is O(n log n). The single loop afterwards is O(n). Total = O(n log n).

Space: O(n) — in the worst case (no overlaps at all), the result list contains all n intervals. If we count only auxiliary space (not the output), it's O(1) — just the current variable and the loop counter.

Tip: always explain the WHY, not just the value. "O(n log n) because sorting dominates" is a much better answer than just "O(n log n)".

4
Bug catch
Your solution works on [[1,3],[2,6],[8,10]] but fails on [[3,5],[1,4]]. Why, and how do you fix it?
▼
✅ Model Answer

The input is unsorted. Starting with [3,5] as current, we check [1,4]: since 1 > 5 is false (1 is less than 5, not greater), we'd actually try to merge... wait — let me re-examine. 1 ≤ 5 is TRUE, so we'd extend current.end = Max(5,4) = 5. Output: [[1,4] merged incorrectly]. Actually the real bug is: we saved [3,5] and set current=[1,4]. Then loop ends. Output: [[3,5],[1,4]] — unsorted output, wrong intervals.

Fix: always sort first. After sorting: [[1,4],[3,5]]. Now 3 ≤ 4 → merge → [1,5]. Correct! This is exactly the candidate's mistake in the interview template. Never assume sorted input.

5
C# syntax
How do you sort a 2D int array in C# by the first element of each sub-array?
▼
✅ Model Answer

Use Array.Sort with a lambda comparator:

Array.Sort(intervals, (a, b) => a[0].CompareTo(b[0]));

a and b are two sub-arrays being compared. a[0] is the first element. CompareTo returns negative (a<b), zero (equal), or positive (a>b) — exactly what Sort expects.

Alternative using LINQ: intervals = intervals.OrderBy(x => x[0]).ToArray(); — cleaner but creates a new array instead of sorting in-place.

SQL Customer Analytics

7 Questions
6
Core concept
What does GROUP BY do in SQL? What happens if you forget it when using SUM or COUNT?
▼
✅ Model Answer

GROUP BY divides rows into buckets by a shared value, then runs aggregate functions (SUM, COUNT, AVG, MAX) separately on each bucket.

If you forget GROUP BY when using SUM: SELECT customer_name, SUM(order_amount) FROM orders — SQL gives an error or returns one row for the entire table (depending on the DB). You'd get the grand total of ALL customers combined, not per-customer totals.

Rule to remember: any column in SELECT that is not inside an aggregate function MUST appear in GROUP BY.

7
Syntax detail
What is the difference between COUNT(*) and COUNT(column_name)?
▼
✅ Model Answer

COUNT(*) counts every row — even rows where all columns are NULL.

COUNT(column_name) counts only rows where that specific column is NOT NULL. If some rows have a null value in that column, they're excluded.

In this query COUNT(order_id) is used because order_id is a primary key (never null), so both give the same result. But knowing the distinction matters — it's a common interview question and a source of real bugs when columns can be null.

8
Window functions
What is a window function? How is RANK() OVER different from using GROUP BY?
▼
✅ Model Answer

A window function calculates across a set of rows without collapsing them into a single row.

GROUP BY + aggregates: 5 rows → 3 rows. Rows are collapsed. You lose access to individual rows.

Window function RANK(): 3 grouped rows → still 3 rows, but with an added rank column. Rows are NOT collapsed. You keep all the data plus the rank.

The OVER(...) clause defines the "window" — the set of rows the function operates on and how they're ordered. Without OVER, RANK() would be a syntax error in standard SQL.

9
Ranking functions
What is the difference between RANK(), DENSE_RANK(), and ROW_NUMBER()? Give a concrete example.
▼
✅ Model Answer

Say three customers spent 1000, 1000, and 700 (a tie at the top):

  • ROW_NUMBER(): 1, 2, 3 — always unique, arbitrary order for ties. No concept of "tied".
  • RANK(): 1, 1, 3 — tied values share rank 1, but the next rank jumps to 3 (skips 2). Gap!
  • DENSE_RANK(): 1, 1, 2 — tied values share rank 1, next rank is 2. No gap.

Use DENSE_RANK when you don't want gaps (most business reports). Use RANK when position-in-sort-order matters. Use ROW_NUMBER when you need a unique identifier for each row (e.g., pagination).

10
Common mistake
I want only the top 3 spenders. Can I write WHERE spend_rank <= 3? Why or why not?
▼
✅ Model Answer

No, this will fail with an error. SQL's logical execution order is: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. Window functions (including RANK) are calculated during the SELECT phase — after WHERE has already run.

So when WHERE tries to use spend_rank, that column doesn't exist yet.

Correct approach — use a CTE:

WITH ranked AS ( SELECT customer_name, SUM(order_amount) AS total, RANK() OVER (ORDER BY SUM(order_amount) DESC) AS rk FROM orders GROUP BY customer_name ) SELECT * FROM ranked WHERE rk <= 3;

The CTE computes the rank first, then the outer query filters on it. This is a very common senior SQL interview pattern.

11
Execution order
In what order does SQL actually execute the clauses of a SELECT statement?
▼
✅ Model Answer

SQL does NOT execute top-to-bottom. The logical execution order is:

  1. FROM — identify the source table(s)
  2. WHERE — filter individual rows (before grouping)
  3. GROUP BY — group the remaining rows
  4. HAVING — filter groups (like WHERE but after grouping)
  5. SELECT — compute columns, apply aliases, run window functions
  6. ORDER BY — sort the final result
  7. LIMIT / TOP — trim the result set

This explains: why you can't use a SELECT alias in WHERE (WHERE runs before SELECT), why window functions can't be in WHERE, and why HAVING is used to filter aggregates (e.g., HAVING SUM(amount) > 1000).

12
WHERE vs HAVING
What is the difference between WHERE and HAVING? When do you use each?
▼
✅ Model Answer

WHERE filters individual rows before grouping. HAVING filters groups after grouping.

Use WHERE when filtering based on a raw column value: WHERE order_amount > 100 — remove individual orders under 100 before any grouping.

Use HAVING when filtering based on an aggregate result: HAVING SUM(order_amount) > 500 — only keep customers whose total exceeds 500, after grouping.

You can combine both: WHERE order_amount > 50 GROUP BY customer HAVING COUNT(*) > 2 — first remove orders under 50, then group, then only keep customers with more than 2 remaining orders.

LINQ in C#

6 Questions
13
Fundamentals
What is LINQ? Why use it instead of a manual foreach loop?
▼
✅ Model Answer

LINQ (Language Integrated Query) is a set of extension methods and keywords in C# for querying and transforming collections in a declarative, readable style.

Instead of: "create a new list, loop through items, check each one with an if, add matching ones to the list" — you write: items.Where(x => condition).ToList(). The intent is clear in one line.

Key advantages: readable and composable (chain operations), works on any IEnumerable (arrays, lists, dictionaries, EF Core DbSets), type-safe at compile time, and with EF Core it translates C# to SQL automatically.

14
Lambda
Explain this line: orders.GroupBy(o => o.Customer). What does each part mean?
▼
✅ Model Answer

o => o.Customer is a lambda expression (an inline function).

  • o — input parameter. Represents one Order from the collection. The name is arbitrary — you could call it order or x.
  • => — reads as "goes to" or "such that".
  • o.Customer — the return value. For each Order, return its Customer property.

So the whole call means: "From the orders list, group them by each order's Customer property." The result is an IEnumerable<IGrouping<string, Order>> — a collection of groups where each group's Key is a unique customer name.

15
GroupBy internals
After GroupBy, what is g in the next .Select(g => ...)? What properties does it have?
▼
✅ Model Answer

g is one IGrouping<string, Order> — a single customer's group of orders. It has two important things:

  • g.Key — the grouping value (the string you grouped by). For Alice's group, g.Key = "Alice".
  • g itself is IEnumerable<Order> — you can iterate it or call LINQ methods on it. So g.Sum(o => ...) sums across all of Alice's orders.

This is exactly how TotalSpend = g.Sum(...) works — it's summing over all orders in that one customer's group.

16
Nested sum
Why does the LINQ solution have two nested Sum() calls? Explain each one.
▼
✅ Model Answer

Because the data is nested two levels: Customer → Orders → Items. We need to sum at each level.

Inner Sum — o.Items.Sum(item => item.Quantity * item.Price): For one Order o, loop its Items, multiply Quantity × Price for each item, and sum them. This gives one order's total value.

Outer Sum — g.Sum(o => [inner sum]): For all orders o in the customer's group, get each order's total (inner sum), then add all those order totals. This gives the customer's grand total across all orders.

The reason for two levels: a single g.Sum(o => o.Price) wouldn't work — Order doesn't have a Price; the price is on each Item inside the order.

17
Deferred execution
What is deferred execution in LINQ? Why does it matter in production code with EF Core?
▼
✅ Model Answer

Deferred execution means the LINQ query doesn't execute when you write it — it executes only when you iterate over the results.

Methods like Where, Select, GroupBy, OrderBy, Take, Skip are deferred — they build an expression tree (a "recipe") but don't run it.

Execution is forced by: ToList(), ToArray(), foreach, Count(), First(), Sum() etc.

Why it matters with EF Core: If you iterate a LINQ query twice (e.g., once to check Any() and once in foreach), it hits the database TWICE. This is the N+1 problem. Fix: call .ToList() once to materialise the data, then use the in-memory list as many times as needed.

18
Senior-level
What is the N+1 problem in EF Core LINQ? How do you prevent it?
▼
✅ Model Answer

The N+1 problem: you load a list of entities (1 query), then loop over them accessing a related navigation property — triggering a new database query for each item (N more queries). Total: N+1 round trips.

Example of the bug:

var orders = context.Orders.ToList(); // 1 DB query foreach (var o in orders) Console.WriteLine(o.Customer.Name); // 1 DB query PER order → N queries!

Fix 1 — Eager loading with .Include():

var orders = context.Orders .Include(o => o.Customer) // JOIN in SQL — 1 query total .ToList();

Fix 2 — Select only what you need (projection):

var names = context.Orders .Select(o => o.Customer.Name) // SQL handles the JOIN .ToList();

This is one of the most valued topics in senior .NET interviews — it demonstrates real production awareness, not just syntax knowledge.
